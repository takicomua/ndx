# Grok ↔ Cursor bridge

Прямого API між **Grok Bot** і Cursor немає. Ця папка — спільна черга задач у репозиторії.

## Як це працює

| Файл | Хто пише | Хто читає | Призначення |
|------|----------|-----------|-------------|
| `INBOX.md` | Grok (або ти з Grok) | **Cursor** | Задачі на виконання в коді |
| `OUTBOX.md` | **Cursor** | Grok (або ти) | Результат, статус, питання |
| `CONTEXT.md` | будь-хто | обидва | Короткий спільний контекст проєкту |

## Workflow

1. У Grok Bot попроси: *«Запиши задачі для Cursor у форматі INBOX»* (шаблон нижче).
2. Скопіюй відповідь у `bridge/grok/INBOX.md` **або** збережи файл напряму, якщо Grok має доступ до цієї папки.
3. У Cursor напиши: **`@bridge/grok/INBOX.md виконай задачі від Grok`** (або просто «перевір inbox»).
4. Cursor виконає й оновить `OUTBOX.md`.
5. Кинь `OUTBOX.md` назад у Grok для наступного аудиту / задач.

## Шаблон задачі для Grok (копіюй у Grok як інструкцію)

```
Коли даєш технічні задачі для репо ndx.com.ua, відповідай ТІЛЬКИ блоком Markdown
у такому форматі (готовий до вставки в bridge/grok/INBOX.md):

# Inbox · Grok → Cursor
Оновлено: YYYY-MM-DD HH:mm

## Задачі
- [ ] **ID-1** Короткий title
  - Що зробити:
  - Файли / шляхи (якщо відомо):
  - Done when:
  - Пріоритет: P0 | P1 | P2

## Нотатки для Cursor
(контекст, обмеження, чого НЕ робити)
```

## Швидкі команди в Cursor

- `перевір grok inbox` — прочитати `INBOX.md` і виконати відкриті `- [ ]`
- `звіт у grok outbox` — коротко записати статус у `OUTBOX.md`
